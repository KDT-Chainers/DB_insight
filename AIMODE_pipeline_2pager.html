왜 LangGraph 인가

Why
01 · 문제정의

일반모드

"이 파일 어디?" 위치 찾기 · 결과 = 파일 카드

AIMODE

"결론이 뭐야?" 문서 내용 합성 · 결과 = 완성된 한국어 답변 + 인용

→ AIMODE 는 검색이 아니라 합성. 단순 함수 한 줄로 안 풀림.

02 · Naive RAG 한계
질문 → 벡터검색 → concat → LLM → 답
✕ 분기 없음잡담·인용·후속 다 같은 경로
✕ 후속 불가"전년 대비?" 도 처음부터 재검색
✕ 페이지 인용 X"40페이지" 식 정확 위치 못 줌
✕ 진행 표시 X스피너만 도는 깜깜이 UX
✕ 폴백 없음매칭 약해도 강제 환각 답
✕ 상태 보관 어려움인자 폭발, 시그니처 더러움
03 · LangGraph 4 도구
① StateGraphRAGState dict 자동 공유 → 인자 0개
② 조건부 엣지add_conditional_edges 한 줄로 분기
③ MemorySaverthread_id 만 같으면 state 자동 복원 → 후속 자연
④ 노드 단위 SSE_emit() 으로 단계별 진행 표시

셋업 (정적 구조)

Setup
왜 AIMODE 는 단순 함수가 아닌가
문제정의

AIMODE = 합성(synthesis). 로컬 DB 위에서 사용자 질문에 답을 만드는 일. 단순 파일 찾기와 다름.

Naive RAG (비교군)

질문→벡터검색→LLM 단방향. 분기·후속·페이지인용·진행표시·폴백 모두 부재.

LangGraph 4 도구

StateGraph · 조건부 엣지 · MemorySaver · 노드 단위 SSE. Naive 가 못 풀던 6가지를 정확히 풀어줌.

전체 그래프 (10 노드 + 폴백 마커)
노드 명세 (10 + 1 폴백)
1routerrag/followup 분기 판단
2intentstructured/open 모드 + 키워드 추출
3searchBGE-M3 벡터 검색 top-K
4scan페이지 단위 substring + phrase 매칭
5selectconfidence gate (점수 컷·목차 페널티)
6fulltext_searchopen 모드 — 전 페이지 직접 스캔
7followup_intent이전 sources 회수 + 후속 kw
8followup_search이전 페이지 캐시 재스캔
9extractreferences (page·snippet) 정규화
10generateOllama 스트리밍 + SQLite 영속
ⓕ_fallback_markerfollowup 실패 → RAG 사이클 점프
RAGState — 모든 노드가 공유하는 상태
class RAGState(TypedDict):
  question: str          # 사용자 질문
  thread_id: str         # 채팅방 ID
  history: list[dict]   # 이전 turn
  route: str             # "rag" | "followup"
  mode: str              # "structured" | "open"
  file_keywords: list     # 파일 매칭용
  detail_keywords: list   # 페이지 매칭용
  candidates: list[dict]   # 벡터검색 후보
  matched_sources: list   # select 통과
  references: list[dict]  # 인용 청크
  answer: str            # streaming 누적
