01 · 문제정의

우리가 풀려고 하는 문제

일반모드와 AIMODE 는 사용자가 시스템에 기대하는 것 자체가 다릅니다. AIMODE 는 단순 검색이 아니라 로컬 DB 위에서 사용자의 질문에 답을 만들어내는 일 입니다.

M 일반모드 (MainSearch)

"이 파일 어디 있어?"

  • 파일·이미지·동영상 위치 찾기
  • 쿼리 ↔ 메타데이터 매칭 (BGE-M3 / SigLIP2 / CLAP)
  • 검색 결과 = 파일 카드 리스트
  • 최종 산출물: 사용자가 직접 파일 열어봄

A AIMODE

"그래서 결론이 뭐야?"

  • 로컬 DB 의 문서 내용 자체를 읽음
  • 여러 페이지를 모아 답변을 합성
  • 검색 결과 = 완성된 한국어 답변 + 인용
  • 최종 산출물: 답 자체. 사용자는 출처만 검증

→ AIMODE 는 검색이 아니라 합성(synthesis) 의 영역. 단순 함수 한 줄로 풀리지 않습니다.

02 · 비교군

Naive RAG 로는 안 되는 이유

교과서적 RAG 는 단방향 직선 흐름입니다. 사용자가 실제로 던지는 다양한 질문 패턴을 받아낼 수 없습니다.

✕분기 없음

잡담이든 문서 인용이든 후속 질문이든 모든 입력이 같은 경로. "안녕"에도 PDF 를 뒤짐.

✕후속 질문 불가

"전년 대비는?" 같은 후속에서도 처음부터 다시 검색. 직전 turn 의 문서 컨텍스트는 버려짐.

✕페이지 단위 인용 불가

문서 전체를 한 덩어리로만 매칭. "40페이지에 있다" 식 정확한 인용 위치를 줄 수 없음.

✕진행 표시 없음

사용자는 그저 스피너 보고 기다림. 어디까지 진행됐는지, 어떤 파일을 보는지 알 수 없음.

✕폴백 없음

매칭 실패해도 1순위 문서를 강제로 답하는 환각. "그건 모릅니다" 도 못 함.

✕상태 보관 어려움

thread 단위 history, 직전 sources, references — 매 호출마다 인자로 들고 다님. 함수 시그니처 폭발.

03 · 해결책

그래서 LangGraph

Naive RAG 가 못 풀던 문제는 결국 모두 "그래프 자료구조"의 부재. LangGraph 는 정확히 그 4가지 도구를 줍니다.

① StateGraph — 노드 간 상태 자동 공유

모든 노드가 RAGState 라는 dict 를 입력받고 일부 필드만 update 한 dict 를 반환. 함수 인자로 history·sources·references 를 들고 다닐 필요 없음.

class RAGState(TypedDict):
  question: str
  history: list[dict]
  candidates: list[dict]
  matched_sources: list[dict]
  references: list[dict]
  answer: str

② 조건부 엣지 — 질문 종류별 다른 경로

한 줄로 분기 정의. 라우터·intent·followup 모두 다음 노드를 동적으로 선택.

builder.add_conditional_edges(
  "router", _route_edge,
  {"rag": "intent",
   "followup": "followup_intent"})

③ MemorySaver — 후속 대화 자연 연결

thread_id 만 같으면 LangGraph 가 자동으로 직전 state 를 불러옴. 후속 질문에서 직전 sources / history 가 그대로 살아 있음.

checkpointer = MemorySaver()
graph.compile(checkpointer=checkpointer)
# 이후 thread_id="t_abc" 로 재호출 시 state 복원

④ 노드 단위 SSE — 실시간 진행 표시

각 노드가 진입 / 진행 / 완료 시점에 SSE 이벤트를 push. 프론트엔드는 단계별로 카드를 그려줌. 사용자가 "지금 뭐가 일어나는지" 알 수 있음.

_emit({"type": "scanning",
       "file_name": src.name,
       "index": i})

scan_node

10 · 노드 5/7 (1턴)
L
select_node
Confidence gate — 1순위 강제 fallback 폐지. 매칭 점수가 컷오프 이하면 "답할 수 없음" 도 인정.

왜 confidence gate?

Naive RAG 의 가장 큰 문제: 매칭이 약해도 top-1 을 답해버려서 엉뚱한 환각 답변이 나옴.

로직

  • 최소 score 컷: 일정 점수 미만은 버림
  • 목차 강하면 제외: is_toc_strong 판정 시 본문에 못 가도 답 안 함
  • 전부 컷 통과 못 하면: matched_sources = []
    → generate 에서 "제공 문서에 해당 정보가 없습니다" 출력

15 · followup 노드 2개

followup_intent  +  followup_search

직전 sources 의 페이지 캐시 안에서만 매칭 — 새 벡터검색을 돌리지 않아 빠르고 맥락 보존.

① followup_intent_node

  • 직전 turn 의 last_sources 회수 (state 에 저장돼 있음)
  • 후속 질문에서 새 키워드 추출 (예: "전년 대비")
  • 키워드 분해: "SW산업 수출액 전년대비" → phrase + 토큰
    → ["SW산업 수출액 전년대비", "SW산업", "수출액", "전년대비"]
SSE EMIT {"type": "followup_intent",
 "reused_sources": [...],
 "keywords": [...]}

② followup_search_node

  • last_sources 의 PDF 페이지 캐시만 다시 스캔
  • 벡터검색 X — 이미 매칭된 문서 안에서 새 키워드만 매칭
  • matched_pages ≥ 1 → exist → extract 로 진행
  • 매칭 0 → none → 폴백 사이클
matched = []
for src in last_sources:
  pages = _scan_pdf_pages(src.path,
                          keywords)
  if pages:
    matched.append({**src,
                    "matched_pages": pages})
return {"matched_sources": matched}

📄 PDF 정리 버튼

대화가 일단락되면 입력창 안의 PDF 버튼 한 번. LLM 이 대화 전체를 매거진 스타일로 요약한 PDF 가 다운로드됩니다.

흐름 (LangGraph 와 독립)

  • ① 프론트가 POST /api/aimode/export-pdf {thread_id}
  • ② 백엔드가 SQLite aimode_messages 에서 모든 turn 로드
  • ③ LLM (Ollama gemma3) 으로 정리 JSON 생성
    {title, overview, key_points, qa_summaries, conclusion}
  • ④ reportlab 으로 PDF 합성 — Cover · Key Points · Q&A · Conclusion 4섹션
  • ⑤ 한글 폰트 자동 등록 (Malgun Gothic)
  • ⑥ 파일명: {제목}_{날짜}.pdf 자동 다운로드

PDF 디자인 (editorial 매거진)

  • 섹션 라벨 + 파란 짧은 바 + 큰 번호 타이틀
  • Cover: 제목 + 메타 그리드 (대화방·대화 수·생성·출력)
  • Key Points: ◆ 다이아몬드 마커 + 번호
  • Q&A summary: 굵은 진남색 Q + 들여쓰기 A
  • Conclusion: 진남색 풀쿼트 카드 + 흰 본문
  • 매 페이지 푸터에 페이지 번호 (01, 02, …)

이 기능은 LangGraph 그래프와는 별도 — 그래프가 만든 영속 데이터(SQLite)를 재활용하는 downstream 기능입니다.
